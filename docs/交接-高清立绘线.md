## 2. ⚠️ 两处需要你知情的

### 2.1 `温德冽.png` 是重复孤儿（我只报告，不动手）

- 它与 `旋风多比.png` **字节完全相同**（SHA256 都是 `0A93C719D940BB9C…`，都是 156,536 字节）。
- 依据本项目**第 31/32 轮的裁定**：`温德·冽 多比` 的动作组原文就是「用未知图案代替」，
  原版**没给它画立绘**；那张图判给了「旋风多比」。
- 所以 `温德冽.png` 是改判前的遗留副本，`forms` 与 `artOnly` **两边都没引用**。
- 我一度删掉它，后来**已还原**（不在高清线的地盘上擅自删素材）。**要不要清理由高清线决定。**
- 参考：`_tools/gen-form-walk.mjs` 里加了"只给真被引用的立绘生成走路帧"的过滤，
  所以留着它也不会再产出孤儿帧。

### 2.2 渲染设置：`imageSmoothingQuality = 'high'`

- 位置：`game/engine/engine.js` 的 `util.drawSprite()`，在 `drawImage` 之前逐次设置。
- 原因：浏览器这个值**默认是 `'low'`**，而全项目从来没设置过；立绘是 640px → 132px 的**大幅缩小**绘制，
  `'low'` 在 5 倍缩小下会明显发糊。
- 性质：这是**渲染侧**的一行设置，不生成、不修改任何图片，与"立绘高清化"不冲突（一个管画质过滤，一个管图源）。
- **如果高清线也要处理这块，说一声，我撤掉。** 我没有继续往这个方向做任何事。

## 4. 我这边的任务是什么（免得混淆）

用户原话：「把每个多比的走路[动作]都改成和 NPC 一样。主角走路模式太怪了，就像在空中飘动一样。」

查清的事实（供高清线参考，可能对你们有用）：
- **NPC 看着对**，是因为用的是 `时装序列` 的**真走路帧**（43 套 × 正面/背面 × 17~31 帧，218×320，fps 24）。
- **归档里没有多比的走路循环**：`多比形态序列` 只有 **2 只**（光多比 / 凤凰多比），
  且全是**战斗动作**（发招一~四 / 闪躲 / 防御 / 胜利 / 普通姿态 / 动作一~六）。
  → 如果高清线将来补多比动画，**走路循环是缺的**，这是个已知缺口。
- 52 只形态里**只有 27 只有官方立绘**，另外 19 张官方立绘在 `artOnly`（"仅形象 · 无官方数值"）；
  剩余 25 只形态**归档里没有立绘**，只能画色块占位 —— 这是高清线最值得投入的地方。
