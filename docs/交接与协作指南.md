# 交接与协作指南（v0.9）

> **这份文档是给「接手的人」和「协作的 AI」看的。** 目标：让你在**不改坏东西**的前提下，
> 5 分钟看懂现状、30 分钟能跑起来、第一个改动能安全合并。
>
> 配套：`00-PLAN.md`（唯一权威规则源）· `STATE.md`（现状一页纸）· `docs/复刻与构建手册.md`（从零重建的确切命令）。

---

## 0. 三十秒看懂这是什么

《多克多比》的**离线单机 Web 复刻版**（原版是 2011 年的 Flash 页游，已停服）。

- **技术栈**：纯 HTML + Canvas 2D + 原生 JavaScript（ES5/ES6），**零依赖、零构建**
- **怎么跑**：双击 `多克多比.exe`（自带本地服务器）；或直接浏览器打开 `web/game.html`
- **代码规模**：`game/game.js` 约 1.3 万行（主逻辑）+ 30 多个模块；`_tools/` 约 200 个零依赖 Node 脚本
- **数据规模**：93 个场景 · 52 只多比形态 · 136 个技能 · 36 只怪物 · 17 个小游戏

## 1. 五条铁律（先记住，否则你的改动会被拒）

| 规则 | 含义 | 为什么 |
|---|---|---|
| **R1 不许编** | 归档里查不到的，就写"查不到"，**不许拿推算值冒充原版** | 这是复刻项目，编出来的东西会污染整个数据库 |
| **R4 原始素材只读** | `多克多比专区资料素材/`、`_rar_extracted/` **绝不修改** | 那是一次性证据来源，改了就再也无法复核 |
| **R5 实测** | 断言必须来自**实际运行**，不许写"应该是" | 项目里几乎所有真 bug 都是靠实测抓到的 |
| **R6 测试只加不减** | 断言数下降会被 `run-all-tests.mjs` 的基线守卫抓住 | 防止"改坏了就把测试删掉" |
| **R12 单一事实源** | 数字/版本/状态只在**一处**定义，别处引用 | 文档与实测不一致会被 `check-plan-freshness.mjs` 判红 |

> **一句话**：宁可少做一点，也不许编、不许改证据、不许删测试。

## 2. 每轮改动的标准流程（AI 请严格照这个走）

```
① node _tools/check-plan-freshness.mjs      # 开工自检，14 项必须全过
② 读 docs/自主迭代日志.md 的最近 1~2 轮      # 知道上一轮干了什么
③ 只做**一个主题**的改动                     # 一轮一个主题，别混着改
④ node _tools/run-all-tests.mjs             # 全量回归，0 失败才继续
⑤ 需要的话重建字形：三步流水线（见 §4）
⑥ node _tools/make-release.mjs --ver=0.9    # 出包
⑦ 冒烟：node _tools/smoke-exe.mjs           # 验证 exe 真能起
⑧ 追加 docs/自主迭代日志.md 一轮            # 写清：做了什么/为什么/踩了什么坑
⑨ 更新 STATE.md 与 00-PLAN.md 的数字         # 让 ① 仍然全过
```

**第 ⑧ 步不是走过场**：日志是下一轮（可能是**另一个 AI**）的唯一线索。
写清"我试过 X 失败了，因为 Y"，能省掉后面的人重复踩坑。

## 4. 三个最容易踩的坑（都是实测踩出来的）

### 坑 1：加了中文却不重跑字形 → `test-glyphs` 必红

字形是**预渲染的图集**，源码里出现的任何汉字都必须在图集里。加了一句新文案就要重跑**三步**：

```bash
node _tools/gen-glyphs-prep.mjs
node _tools/with-bom.mjs _tools/glyphs/_gen.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File _tools/glyphs/_gen.ps1
node _tools/gen-glyphs-post.mjs
```
> 只跑第一步的话 `index.json` 不更新 —— 这是最常见的"改了一句话就红"。

### 坑 2：改了生成物 → 下次重跑生成器时你的改动消失

带"**自动生成，勿手改**"抬头的文件：`game/tables/skills-official.js`、`game/tables/form-skills-official.js`、
`assets/forms.js`、`assets/gamedata.js`。**要改就改生成器**（`_tools/` 下同名脚本），
或者加一层**运行时覆盖**（推荐，见 §6 的 `loadouts` 例子）。

### 坑 3：输入状态卡住 → "点什么都不动"

输入清帧（`input.clearFrame()` + `M.endFrame()`）**必须在帧末兜底清一次**。
`update()` 里有 39 处 `return`，靠分支自己清必然漏 → 症状是**点一下之后鼠标键盘全失灵**。
改成帧末统一清之后就再没出现过。**新增任何 `return` 都不用再管这事。**

## 5. 怎么验证你的改动（三层，从弱到强）

| 层 | 手段 | 适用 |
|---|---|---|
| L1 静态 | `node --check <file>` + 读代码 | 任何改动先过这层 |
| L2 断言 | 写 `_tools/test-xxx.mjs`，用 `game-harness.mjs` 加载游戏跑真逻辑 | **推荐主用**。项目有 54 个测试文件 / 2218 项断言 |
| L3 视觉 | `node _tools/shoot.mjs <输出目录>` 拍截图 | 界面改动**必须**拍照核对 |
| L4 真机 | 双击 `多克多比.exe` 玩一遍 | 发布前必做 |

**L3 为什么必做**：本项目抓到的界面 bug（技能图标空占位、文字压住按钮、格子裁歪）
**全部**是拍照看出来的 —— 断言抓不到"长得不对"。

**写测试的最小骨架**：

```js
import { T } from './game-harness.mjs'
T.load('game/game.js')
await T.settle()
const W = T.get('window')
const D = W.DKDbbData
const DBG = () => W.__DKDbb_DEBUG__      // 调试接口：只读，供测试检查状态
// 断言 → process.exit(bad ? 1 : 0)
```
> 注意：`T.step(1)` 跑一帧；**探针脚本必须用 `_` 前缀命名**，否则会被自动发现成测试。

## 6. 三个"照着做就行"的任务模板

### 模板 A：补一个技能图标

1. 找到带名字的图标来源（如 7k7k 角色大全的条目缩略图）
2. **必须"名字+元素"双重确认**才能与官方技能表对上（只靠长得像会张冠李戴）
3. 按游戏既有编号规则命名：`skill_icon_<元素位><三位序号>.png`
   （`1=物理 2=火 3=水 4=土 5=风`；毒/光/暗为本项目新增约定 `6/7/8`）
4. 把映射写进 `assets/skill-icons-7k7k.json`，重跑 `_tools/rebuild-7k7k-skill-icons.mjs`
5. 验证：`node _tools/verify-skill-icons-wired.mjs`（核"表里每个 icon 的文件都在磁盘上"）

### 模板 B：加一套可配置的数据（照 `loadouts` 的做法）

配招系统是**运行时覆盖**的标准范例，照抄它就不会踩"改生成物"的坑：

| 步骤 | 文件 | 做什么 |
|---|---|---|
| ① 存档字段 | `game/engine/engine.js` 的 `defaults` | 加字段（如 `loadouts: {}`），老档自动补 |
| ② 覆盖层 | `game/game.js` | 写 `loadoutOf()` / `setLoadout()`，**覆盖在内存对象上** |
| ③ 单点生效 | — | 覆盖 `S.form.skills` 后，**13 个读取点一处都不用改** |
| ④ 持久化 | — | 改完调 `save.persist()` |
| ⑤ 测试 | `_tools/test-loadout.mjs` | 覆盖"能装/能卸/不超限/不脏/不重复" |

### 模板 C：把界面改成可点击

项目要求**局内所有东西都能左键点击**（不能只支持键盘）。
审计工具：`node _tools/audit-click-coverage.mjs`（会列出"只支持键盘"的模式，目标 0 个）。

做法固定三步：
1. 抽出**坐标表函数**（如 `questRowRects()`）—— **绘制与命中测试共用**，别各算一遍
2. 绘制里改为遍历这张表
3. 输入分支加：`const h = xxxHit(mx,my); if (h) {...}; M.applyCursor(cvs, !!h)`

## 7. 已知的坑清单（接手前先看，能省几小时）

| 现象 | 真因 | 怎么办 |
|---|---|---|
| `test-glyphs` 红，报"缺 N 个" | 新加的中文不在图集 | 跑 §4 坑 1 的三步 |
| `check-plan-freshness` 红 | 文档数字与实测不一致 | 按提示改文档；**不许改脚本迁就文档** |
| 界面显示橙方块/空白格 | 图标文件不存在（字段有值≠文件在） | 跑 `verify-skill-icons-wired.mjs` |
| 点一下之后就没反应 | 输入清帧被 `return` 绕过 | 已修（帧末兜底）；你若新加输入系统请同样兜底 |
| 装了包里的 DLL 后游戏起不来 | 正常 —— **本仓库的沙箱不允许启动 GUI** | 让**人**双击 `多克多比.exe` 验证 |
| 探针脚本被当成测试跑 | 命名没有 `_` 前缀 | 改名 `_probe-*.mjs` |
| `shoot.mjs` 拍出来是空白 | 无头像素画布不解 JPEG | 用现成的预解码缓存（见手册） |

## 8. "融合"别人的改动时怎么做

如果另一条线（或另一个 AI）也在改这个仓库，**合并前必做**：

```bash
node _tools/check-plan-freshness.mjs     # 先确认基线没被动过
node _tools/run-all-tests.mjs            # 再确认回归 0 失败
```
有问题的话，**先修测试再合功能** —— 顺序反了会分不清是谁弄坏的。

**冲突高发区**（改动前先跟对方说一声）：
- `game/game.js`（大家都在改同一个大文件）
- `assets/skills/index.json`、`assets/forms.json`（生成物，谁重跑生成器谁覆盖）
- `docs/自主迭代日志.md`（追加式，冲突好解决）

**降低冲突的写法**：
1. 能加新文件就别改老文件（新模块 / 新 `_tools/gen-xxx.mjs`）
2. 能写"运行时覆盖层"就别改生成物（见模板 B）
3. 必须改 `game.js` 时，**改动集中**、带上解释为什么的注释

## 9. 现状与缺口（v0.9）

**已完成**：可玩通主线（主菜单 → 世界地图 → 93 场景 → 回合制战斗 → 图鉴 → 副本 → 小游戏）、
存档版本化迁移、**84/136 个技能有图标**、**配招系统（可自由搭配）**、52 只形态、白色彩晶石经济。

**v1.0 还差**（详见 `docs/v1.0符合度清单.md`，共 24 项：对齐 9 / 推算占位 10 / 缺依据 5）：

| 缺口 | 数量 | 说明 |
|---|---|---|
| 多比形态立绘 | 缺 **23** 只 | 归档里确实没有；需要**新的带名字的图源**（用户已在找） |
| 技能图标 | 缺 **52** 个技能 | 同上：7k7k 角色大全没覆盖到 |
| 绑定 / 系列技能图标 | 1 个规则未实现 | 小游戏规则原文已读出但机制未做 |
| 场景官方名 | 72 个仍是按画面内容起的 | 等工作表填写 |
| 数值类（伤害系数/掉落表等） | 缺依据 | 归档里没有 → 决策点 D6 |

**⚠️ 不要自己去"补"这些缺口** —— 缺依据就是缺依据（R1）。
正确做法是**找新证据**：能查到出处的图源、截图、策划表。找到后按模板 A 接入。

八项全打勾，你的改动就能安全合并。
